# C.S.P. Chat — Common Support Program

C.S.P. Chat is a compact, security-focused real-time community chat built with Flask, Flask-SocketIO, SQLAlchemy, PostgreSQL/SQLite, and vanilla JavaScript.

## Included

- Accounts with PBKDF2 password hashes, CSRF protection, secure session cookies, 30-minute inactivity expiry, and non-enumerating login errors.
- Public rooms: `general`, `random`, and `tech`, plus user-created rooms.
- Private one-to-one direct messages with separate message history.
- Real-time WebSocket messaging, typing indicators, online/away presence, read receipts for DMs, reactions, replies, editing, soft deletion, and pinning.
- Mentions, message search, unread counts, browser notifications, embedded notification beep, and dark/light themes.
- Emoji avatars, display names, room nicknames, optional profanity filtering, admin role, and invite-code generation.
- Global calendar where logged-in users can add events; event deletion is restricted to the creator or admin.
- Built-in `ChatBot` commands: `/help`, `/ping`, `/roll`, `/flip`, `/8ball`, `/joke`, `/time`, `/users`, and `/quote`.
- Database fallback chain: Render PostgreSQL -> Supabase PostgreSQL -> local SQLite -> in-memory SQLite.
- `/health` reports the active persistence backend.
- Security headers, HTML stripping before storage, plain-text DOM rendering, message length limits, rate limiting, origin-bound Socket.IO session use, and ORM-only database access.

## Local development

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
python app.py
```

Then open `http://127.0.0.1:10000`.

For local HTTP development `COOKIE_SECURE` defaults to `false` when `DATABASE_URL` is not set. For HTTPS deployment, set it to `true`.

## Environment variables

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Primary PostgreSQL URL, normally supplied by Render. |
| `SUPABASE_DATABASE_URL` | Optional PostgreSQL fallback. |
| `SECRET_KEY` | Flask session secret. Render can generate it. |
| `PORT` | Listening port; Render supplies it. |
| `COOKIE_SECURE` | Set `true` for HTTPS. |
| `OPEN_REGISTRATION` | `true` for open signup, `false` for invite-only. |
| `PROFANITY_FILTER` | `true`/`false` server default. |

Never commit real database URLs, API keys, or a production `SECRET_KEY` to GitHub.

## Render deployment

1. Push this folder to a GitHub repository.
2. In Render, create a Blueprint from the repository or create the web service and PostgreSQL database manually.
3. The included `render.yaml` defines the web service and PostgreSQL dependency.
4. Verify the service uses:

```text
gunicorn --worker-class gevent -w 1 --bind 0.0.0.0:$PORT app:app
```

5. Render provides `DATABASE_URL`; `SECRET_KEY` is generated by the Blueprint.
6. Open the deployed HTTPS URL and create the first account. The first user is automatically an admin.

### Supabase fallback

Create a PostgreSQL database in Supabase, copy its PostgreSQL connection string, and add it to the Render service as `SUPABASE_DATABASE_URL`. C.S.P. will test the configured databases at startup in this order:

1. Render PostgreSQL
2. Supabase PostgreSQL
3. `sqlite:///chat.db`
4. `sqlite:///:memory:`

The last two are fallbacks only. Render's filesystem is ephemeral, so local SQLite is not durable on Render. Memory storage loses data on restart.

## Security notes

C.S.P. does not store plaintext passwords. Messages are stripped of HTML before they are written to the database and are inserted into the DOM as text-safe content. Database access uses SQLAlchemy ORM/expression APIs rather than application-level raw SQL. Socket.IO actions require an authenticated Flask session and a CSRF token.

The app is designed as a single-instance service: in-memory presence, rate limits, typing state, and Socket.IO broadcasts therefore stay consistent without Redis. Do not increase Gunicorn workers unless you also add a Socket.IO message queue architecture.

External CDN assets are restricted by the application's Content Security Policy. Calendar data and chat content are persisted in PostgreSQL when available.

## Render free-tier caveat

Free web services may spin down after inactivity, and free database offerings have their own storage, lifecycle, and availability limits. Treat the free tier as a small community/test deployment rather than a production durability guarantee.
